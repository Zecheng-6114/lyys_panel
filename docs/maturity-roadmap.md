# lyys_panel 成熟化路线图

> 状态：待用户审批
> 基线：main = 1697f2c（2026-09-27，已完成 P0/P1 安全加固）
> 目标：从"自用 MVP 面板"演进为"可对外发布的成熟面板（1.0）"

---

## 一、现状快照

### 已有能力

| 域 | 现状 |
|---|---|
| 认证 | JWT（24h）+ 服务端吊销（jti + 吊销名单）+ 登录限流 + 初始密码写 0600 文件、首登后删除；JWT 密钥来自 env 或 0600 密钥文件（1697f2c） |
| 监控 | CPU/内存/磁盘/网络实时采集（sysinfo，5s 采样落 SQLite）+ 仪表盘历史曲线（echarts，运行时读 CSS 变量跟随主题） |
| 运维 | 进程管理、systemd 服务管理、日志 tail（journalctl/文件）、文件管理（含上传/下载/编辑/重命名/删除）、软件包（apt/pacman 双家族）、计划任务（cron）、网络查看、Docker 管理 |
| 界面 | 无边框黑白灰主题 + 主题定制（颜色/圆角/背景图/预设/导入导出），亮暗双模式已移除、深浅为独立预设 |
| 部署 | 单二进制（rust-embed 内嵌前端）+ systemd 服务 + panel.env 配置 |
| 安全 | 错误响应脱敏（SafeJson）、主题字段双端校验（防存储型 CSS 注入）、面板数据目录与 *.db 对文件 API 屏蔽 |

### 主要短板（差距分析）

1. **测试几乎为零**：仅 `distro.rs` 有 `#[test]`；前端无任何测试；核心路径（auth/files/packages）无回归保障。
2. **无 HTTPS**：HTTP 明文 + token 存 localStorage，局域网可用、公网不可用。
3. **无 schema 迁移机制**：改表结构 = 删库重建，用户数据无升级路径。
4. **指标无保留策略**：metrics 表只增不减，SQLite 无限膨胀。
5. **单管理员、无 RBAC**：无多用户、无角色、无会话管理页、无改密 API。
6. **无审计日志**：写操作（删文件/装包/重启服务）不留痕。
7. **无备份/自更新**：更新靠人工 `systemctl stop → cp → start`；DB/配置无导出手段。
8. **无告警通知**：阈值告警、webhook/邮件均缺（此前用户决定暂缓）。
9. **仓库卫生**：AI 模块（ai/aimemory/aitools/emotion/websearch）代码仍在仓库中注释停用。
10. **无发布工程**：无 CI、无多平台构建、无安装脚本、无版本发布流程。

## 二、实施步骤（五期，按依赖排序）

### 一期 · 地基（安全与可维护性）——最先做

| # | 任务 | 方案要点 |
|---|---|---|
| 1.1 | **DB 迁移框架** | 新增 `schema_version` 表（单行版本号）+ `backend/migrations/` 目录按序号存 SQL；启动时 `db.rs` 逐版执行未应用迁移，事务包裹、失败即退出。不引重型依赖（手写 ~80 行即可，避免 refinery 与现有 r2d2 连接池的适配成本）。**越晚做代价越大，是 3.1/3.2 的前置。** |
| 1.2 | **指标保留策略** | 后台 tokio 定时任务（每日）：原始 5s 采样保留 7 天，超期数据按小时聚合（avg/max）写入 `metrics_hourly` 保留 1 年；仪表盘历史查询自动按时间跨度选表。 |
| 1.3 | **HTTPS** | `axum-server` + tls-rustls；两种模式：自动生成自签证书（data 目录，首启创建）或指定已有证书路径（env `PANEL_TLS_CERT/KEY`）；HTTP 端口可配置跳转 HTTPS。 |
| 1.4 | **核心路径测试** | 集成测试（`backend/tests/`）：auth 签发/校验/吊销/限流、files 路径穿越与 DB 屏蔽回归、packages 命令注入面、theme 校验器边界；`cargo test` 与 clippy 并列进提交前验证清单（需同步更新 CONTRIBUTING.md 检查项）。 |

### 二期 · 账户体系

| # | 任务 | 方案要点 |
|---|---|---|
| 2.1 | **多用户 + RBAC** | users 表加 `role`（admin/operator/viewer）；`AuthUser` 提取器附带角色，写操作路由统一加角色守卫；前端按角色隐藏入口。迁移框架就绪后以迁移加列。 |
| 2.2 | **账号管理界面** | 改密/改名/增删用户（admin 专属）；密码沿用现有哈希方案；首登强制改密。 |
| 2.3 | **审计日志** | `audit_log` 表（时间/用户/动作/目标/结果），拦截所有非 GET 业务路由写入；日志页新增"操作审计"标签。 |
| 2.4 | **会话管理** | 吊销名单升级为会话表（jti/用户/UA/IP/签发时间），顶栏"在线会话"页可查看/踢出。 |

### 三期 · 可靠性

| # | 任务 | 方案要点 |
|---|---|---|
| 3.1 | **备份/恢复** | 一键导出（SQLite backup API + panel.env 脱敏副本）到指定目录，定时备份（cron 复用）；恢复入口带二次确认。 |
| 3.2 | **自更新** | 检查 GitHub Release → 下载二进制 → sha256 校验 → 写更新脚本（stop/换二进制/start，失败回滚旧文件）→ 经 systemd 触发；全程审计日志留痕。 |
| 3.3 | **告警通知** | 阈值规则表（CPU/内存/磁盘/服务状态），评估器随采样循环运行；通道先做 webhook（通用、可桥接飞书/钉钉），邮件后置；触发/恢复都通知，带冷却时间防轰炸。 |

### 四期 · 体验与仓库卫生

| # | 任务 | 方案要点 |
|---|---|---|
| 4.1 | 移动端适配 | 侧栏抽屉化、表格列优先级折叠（Element Plus 响应式 + 断点样式）。 |
| 4.2 | 仪表盘自定义 | 卡片显隐/排序配置存 settings 表（复用主题配置同一机制）。 |
| 4.3 | 深度运维页 | 容器日志流（WebSocket）、服务单元文件查看、SMART 磁盘健康（读 smartctl）。 |
| 4.4 | AI 模块处置 | 用户定夺：整目录删除（git 历史可寻回）或移出主仓归档。 |

### 五期 · 发布工程

| # | 任务 | 方案要点 |
|---|---|---|
| 5.1 | CI | GitHub Actions：PR 跑 clippy+test+build，tag 触发多平台（x86_64/aarch64 linux）release 产物。 |
| 5.2 | 安装脚本 | `install.sh`（curl 一键）：建用户/目录/systemd 单元/env 模板；卸载脚本。 |
| 5.3 | 版本与文档 | semver + CHANGELOG；README 安装/截图/FAQ 完善；1.0 发布。 |

## 三、功能缺口总表（对照成熟面板）

| 类别 | 已具备 | 缺口（→ 对应任务） |
|---|---|---|
| 安全 | JWT 吊销、限流、脱敏、注入防护 | HTTPS(1.3)、2FA(可选后置)、IP 白名单(可选)、审计(2.3) |
| 账户 | 单管理员 | 多用户/RBAC(2.1)、会话管理(2.4)、改密(2.2) |
| 运维 | 进程/服务/文件/包/cron/网络/Docker | 备份(3.1)、自更新(3.2)、告警(3.3)、证书管理(1.3 附带) |
| 监控 | 实时+历史曲线 | 保留策略(1.2)、进程级监控(4.3 可选) |
| 工程 | 规范体系、钩子 | 测试(1.4)、迁移(1.1)、CI(5.1)、安装脚本(5.2) |

**范围决策待定**：是否纳入"网站/反向代理管理"（Nginx 配置生成、SSL 申请）决定产品定位是"服务器运维面板"还是"建站面板"。建议 1.0 前不做，保持定位聚焦。

## 四、时间估算

前提：单人 + AI 协作，业余投入（每晚+周末约 10–15 小时/周）。全职约按 1/3 折算。

| 阶段 | 内容 | 估算 |
|---|---|---|
| 一期 | 迁移框架 → 保留策略 → HTTPS → 测试 | 2–3 周 |
| 二期 | RBAC → 账号管理 → 审计 → 会话 | 2–3 周 |
| 三期 | 备份 → 自更新 → 告警 | 2 周 |
| 四期 | 体验项（可长期滚动，不卡发布） | 3–4 周 |
| 五期 | CI → 安装脚本 → 1.0 发布 | 1–2 周 |

- **对外可发布 1.0：约 2–3 个月**
- **自用足够稳（一期全部 + 三期备份/告警）：约 3–4 周**

里程碑验收：每期结束跑一次"clippy + test + build + 部署 + 冒烟"，功能期（一/二/三期）结束即具备回退能力（依赖 1.1 迁移与 3.1 备份）。

## 五、风险与对策

| 风险 | 对策 |
|---|---|
| RBAC 改造触碰全部路由，回归成本高 | 依赖 1.4 测试先行；守卫做成提取器参数，逐路由迁移而非一次性重写 |
| 自更新变砖 | 保留旧二进制 + 失败自动回滚脚本；更新前强制触发 3.1 备份 |
| 指标聚合改变仪表盘查询语义 | 新旧表并存一个迭代，前端按时间跨度自动路由，可回退 |
| 多会话并发操作 git/部署（历史教训） | 沿用 AGENTS.md 铁律；路线图执行期间同一时刻只允许一个会话动 git |
